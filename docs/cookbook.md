# 第一次使用 Echo：从录音到一场复盘

这份教程带你走完 Echo 0.0（源码 `0.0.0`）的一次完整流程：**选择文件夹 → 回放 → 60 秒试转 → 全场转写 → 笔记与引用 → Codex 复盘 → 刷新查看**。

准备一份录制完成的面试音频或视频。本文中的目录和笔记都是示例，不包含真实面试资料。模型安装、排错与详细参数分别见 [README](../README.md) 和 [使用指南](usage.md)。

## 1. 启动并选择你的文件夹

先按 [README 的启动步骤](../README.md#启动) 准备 Python 环境，在 Echo 源码目录运行：

```sh
./start.command
```

打开终端实际输出的本机 URL，点击“选择文件夹”（或按 ⌘O）。选中已有媒体所在的目录，例如：

```text
面试资料/
└── 示例公司/
    └── 一面/
        └── 面试录音.m4a
```

选择上面的“面试资料”后，保持默认保存位置，点击“保存并扫描文件夹”。原文件留在原处，之后生成的转写默认放在 `面试资料/echo/示例公司/一面/`；不需要将媒体复制进 Echo 源码。

**应看到：** 资料列表出现该记录。此时即使显示“尚未转写”，也已经可以回放。

**没有找到媒体时：** 确认选中的是包含音视频的文件夹；文件需停止写入至少 60 秒，再扫描一次。支持 MOV、MP4、MKV、WAV、MP3、M4A、WebM。生成结果所在的 `echo/`、旧 `echos/` 和运行数据目录会被排除，不应将它们作为原始录音目录。

## 2. 先听一段，确认选对了记录

打开记录，点击底部播放按钮。用进度条或时间输入跳到一段声音清楚的问答；视频可点击“展开录屏”。需要反复核对时可降低倍速或设置 A–B 循环。

记下清楚问答的开始秒数，供下一步试转使用。例如 2 分钟对应 `120` 秒；若开头就有对话，可以使用 `0`。

**应看到：** 播放位置随媒体前进，能听到预期内容；未转写时逐字稿区域为空，这是正常状态。

**不能播放时：** 检查文件是否仍在原位置，以及浏览器是否支持该文件的容器和编码。没有波形但能播放时，可先用时间轴；真实波形还需要 FFmpeg。基础回放与安装 ASR 模型是分开的步骤。

## 3. 只转写 60 秒

本地转写面向 Apple Silicon Mac。尚未准备转写环境时，先按 [README](../README.md#启动) 安装 FFmpeg 和 `requirements-asr.txt`，然后重启 Echo 服务。首次转写会下载所选模型，需要网络和可用磁盘空间。

点击“语音转文字”，设置：

| 字段 | 第一次试转建议 |
| --- | --- |
| 转写模型 | 保持默认 Qwen3-ASR，或选择已准备好的模型 |
| 语言 | 按录音内容选择；中文技术面试可选中文 / 中英混合 |
| 起点（秒） | 填入刚才记下的开始秒数 |
| 时长（秒，可留空） | 填 `60`，并确认结束位置不超过媒体时长 |
| 术语提示 | 可补充实际出现的技术名词；不确定时保持默认 |

点击“加入处理队列”，在“处理队列”查看状态。这里的 60 秒是音频处理范围，不是预计耗时。若整份录音不足 60 秒，将试转时长缩短到实际剩余范围。

**应看到：** 任务进入等待或执行状态，随后出现完成版本。打开该版本，点击逐字稿时间点回听，核对语言、术语与时间范围。首次下载或模型加载可能较久，不代表已经完成转写。

**不能提交或任务失败时：** 先看模型下方提示和队列错误，核对当前 Python 环境、ASR 依赖、FFmpeg / ffprobe。不要反复提交相同任务。若文字明显不对，先确认声音、语言与术语提示，再决定是否重试；Qwen 的块级时间戳不能当成逐句对齐。

## 4. 确认试转可用，再处理全场

再次点击“语音转文字”，将“起点”改为 `0`，将“时长”清空，表示从开头处理到结尾。重新确认模型和语言与试转时一致，然后加入队列。

60 秒试转与全场的参数不同，不需要为了生成全场结果勾选“重新转写已有结果”。试转会保留；同参数的已完成结果可复用，确实需要重做时再启用该选项。

**应看到：** 全场任务完成后，版本选择器中可以找到它。选择该完成版本，核对覆盖范围，再开始整场复盘；不要继续拿 60 秒试转版本得出整场结论。

**处理期间：** 任务串行执行，关闭网页不会取消后台转写，电脑休眠可能影响处理。排队或运行时不能切换输入、输出目录或输出结构；等待任务结束，或取消尚未开始的任务后再修改。中断任务需要核对后重新提交，不支持半途续算。

## 5. 留下能回听的笔记

在选定的全场版本中搜索或播放一个关键回答。点击逐字稿段落旁的 `＋`，把原文和原媒体时间加入右侧“我的笔记”；再写下你想核对或改进的地方。例如：

> 这段技术名词没有听清，待回听；复盘时先保留不确定性。

**应看到：** 右侧出现带时间点的原文引用，笔记保存状态显示已保存。点击引用可返回相应位置，方便与声音对照。

**保存失败或冲突时：** 保留当前页面的草稿，按提示重试或合并；必要时先导出当前笔记。不要刷新页面试图“修复”尚未保存的内容。技术术语、人物身份或回答含义拿不准时写“待回听”，不要直接将识别错误当作面试表现问题。

## 6. 把当前版本交给 Codex

确认当前场次和转写版本正确，点击“交给 Codex 复盘”。Echo 会先保存笔记，再生成“本场复盘交接”。先阅读显示的材料警告，再点击“复制本场复盘交接”。

在能读取这些本机文件的 Codex 项目中，将交接文字粘贴到聊天并发送。它已经包含选定版本、文件位置、覆盖范围、已保存笔记和复盘目标路径，并要求 Codex 遵循 [复盘标准](codex-review.md)。

**应看到：** Echo 提示已复制；发送后，Codex 根据材料开展分析并将结果保存到交接指定的 `review.path`。**复制只把文字放入剪贴板，不会自动调用 Codex，也不代表复盘已经执行。**

**材料不足时：** 没有有效转写、源文件已变化、只完成试转或完整覆盖尚未核实时，先解决提示的材料问题，或明确只分析已有片段。Codex 仍需读取实际文件；没有播放音视频，不能声称已经回听。切换了转写版本，就重新生成交接。

## 7. 回到 Echo 查看复盘

Codex 写入文件后，回到当前记录，打开“Codex 复盘”页签，点击“刷新文档”。

**应看到：** 复盘正文和对应状态。Echo 只读展示这份文件；要补充回听纠正或练习结果，可以继续让 Codex 按协议追加，再回来刷新。

**仍显示没有文档时：** 展开“文档保存位置”，核对 Codex 实际保存的位置是否与服务指定路径一致。不要凭文件夹名称另建第二份复盘。输出目录中的 `review.md` 是转写核对稿，和 Codex 的 `复盘.md` 不是同一份文档。

**继续和 Codex 讨论时，内容存在哪里？** 本场讨论沿用这份 `复盘.md`，将已确认的结论、用户补充、分歧、待回听项与下一步练习按日期追加到“追加记录”，关联原问题与行动 ID。可以告诉 Codex：“把这轮讨论收敛到同一份复盘的追加记录，区分已确认与待核实。”聊天本身不会自动同步；文件保存后再回到 Echo 刷新。

跨场报告保存在本次确认的输出根目录 `面试总结.md`，先明确日期和纳入哪些面试。要让后续复盘沿用已确认的信息，可按下一步建立 Memory。单场复盘页签不会自动展示跨场总结或 Memory。

## 8. 可选：留下可修订的 Memory

打开“交给 Codex 复盘”，点击“初始化 Memory”。Echo 会在首次初始化时的输出根目录创建 `memory/MEMORY.md`、`memory/profile.md` 和空 `memory/topics/`，并将位置绑定到当前源文件夹。

**应看到：** 交接中显示 Memory 的实际索引路径。初始化只建立空模板，不会自动总结所有面试。将新的交接发送给 Codex 后，可继续说明：

> 先读 Memory 索引，再结合本场复盘提出少量有来源的候选条目。把背景或偏好、主题观察、待回听项分开；我确认后再记为已确认信息。

从当前问题开始维护 1–3 份主题文件即可。候选须引用场次、实际版本、问题 ID 或原媒体时间；用户确认准确含义后再作为确认信息使用。新证据出现时可以更新当前表述，但保留稳定 ID、证据和只追加的修订历史。详细示例见 [Memory 使用与维护](memory.md)。

**下一场怎么用：** 重新生成当前版本的交接，Codex 先读索引，再选相关主题，必要时回到原复盘核对。更改转写输出目录不会移动这份 Memory；以交接中的绑定路径为准。Memory 本身需要备份，真实条目不能提交进公开源码。

走完这次流程后，你应能打开原媒体、选择完成的全场版本、回听笔记中的引用，并在 Echo 中看到 Codex 保存的复盘。保留“待回听”项，之后用回听或重练证据追加纠正；下一场面试从扫描新媒体开始即可。
