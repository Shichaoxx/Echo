# Memory 使用与维护

Memory 是与一个面试源文件夹绑定的本地 Markdown 文件集，用来保存用户确认的背景、偏好和有证据的主题结论。它让后续 Codex 复盘可以沿用已有认识，同时保留纠正这些认识的依据。

Echo 负责初始化空模板、保存资料库绑定，并在交接时提供路径。内容由用户与 Codex 在明确任务范围内维护；Echo 不自动分析全部面试，不运行语义检索，不自动生成画像，也不根据练习结果改写 Skill。

## 初始化与位置

先选择面试文件夹并保存路径，再打开“交给 Codex 复盘”，点击“初始化 Memory”。首次初始化使用当时的输出根目录：

```text
<输出根>/
├── 公司A/一面/复盘.md
├── 面试总结.md              # 按用户指定范围生成的报告
└── memory/
    ├── MEMORY.md            # 索引、阅读顺序和维护约定
    ├── profile.md           # 用户提供或确认的信息
    ├── topics/              # 按需创建主题 Markdown
    └── .echo-memory.json    # 由程序维护的归属标记
```

初始化不提取能力结论，也不会把所有面试整理进模板。开始使用时，围绕当前问题建立 1–3 份主题文件即可；没有证据的栏目可以保持为空。

也可在 Echo 源码目录使用命令行：

```sh
.venv/bin/python -m echo.memory status --data-dir "/path/to/runtime-data"
.venv/bin/python -m echo.memory init --data-dir "/path/to/runtime-data"
```

`--data-dir` 指向工作台使用的运行数据目录，不是媒体目录；省略时使用 `INTERVIEW_DATA_DIR` 或默认 `.local/`。初始化前必须明确配置源文件夹。`status` 只检查状态，不创建模板。

每个源文件夹有独立的 Memory 绑定。为同一源文件夹更改转写输出目录时，绑定仍指向原 Memory，交接继续使用其实际路径。切换源文件夹时使用对应绑定，不混入其他资料库的背景或结论。不要凭当前输出目录手动另建第二套权威 Memory。

路径变化不等于文件迁移。若原 Memory 被移动或其存储盘不可用，先核对备份和已有绑定；不能用一套空模板冒充已恢复的资料。

运行数据目录的 `memory-locations.json` 保存绑定，Memory 内的 `.echo-memory.json` 记录源目录与数据根归属。不要通过手工改写这些文件来接管另一份资料库；初始化不会接管归属不明的既有目录，也不会重建丢失的已绑定内容。

## 各文件保存什么

| 文件 | 权威职责 | 更新方式 |
| --- | --- | --- |
| 单场 `复盘.md` | 本场证据、逐题分析、讨论与回听纠正的历史 | 初次建立结构；后续正文按日期追加，引用 Q/A ID |
| `面试总结.md` | 某个日期、明确范围内的跨场报告 | 记录纳入场次、报告日期和资料不足，引用相关 Memory 条目；后续报告按日期追加 |
| `memory/MEMORY.md` | 简短入口、主题索引和阅读顺序 | 随主题增减维护链接，不重复堆放长篇总结 |
| `memory/profile.md` | 用户提供或确认的目标、背景、交流偏好与约束 | 使用稳定条目 ID；更正当前信息时保留来源和修订历史 |
| `memory/topics/*.md` | 按主题保存当前理解、证据、适用范围和待验证行动 | 当前表述可更新；稳定 ID、证据与修订历史保留 |

`面试总结.md` 不维护另一份权威画像。报告可以引用 Memory 中当时的结论，但必须注明日期和范围；日后 Memory 改变，不应让旧报告看起来也得到了新证据。英文 `review.md` / `review.json` 是转写生成的核对稿，不属于上述 Memory 或 Codex 复盘文档。

## 条目约定

`profile.md` 和主题文件使用 Markdown，由人和 Codex 阅读。每条可持续维护的信息至少包含：

- **稳定 ID**：在同一资料库内唯一，后续引用和纠正沿用原 ID。
- **当前理解**：准确描述当前已知信息，标出适用范围，避免泛化成固定能力标签。
- **状态**：`已确认`、`待回听`、`待验证` 或 `已撤回`；记录用户确认的时间与内容。确认结论和验证练习是两件事；后续证据出现疑点时，可将已有条目重新标为待核实。
- **来源**：实际面试 ID、转写版本 ID、Q/A ID 或原媒体时间范围，以及指向复盘或证据的链接。用户补充的信息注明由用户提供及确认日期。
- **更新时间**：带时区的 ISO 8601 时间，表示当前表述最后更新的时间。
- **修订历史**：只追加，记录日期、原判断、新证据、新判断、确认情况和相关行动。

这些是协作约定，不是自动事实校验。不能编造 ID、时间戳或确认记录来补齐格式；材料缺失时直接写明。

## 从复盘到 Memory

1. **保留证据**：先把单场讨论、回听纠正或练习结果落到对应 `复盘.md`，保留原问题、来源版本和时间。跨场报告先明确纳入范围。
2. **提出候选**：只提炼对后续复盘有用的信息，说明来源、适用范围和不确定性。候选暂存在对应复盘的讨论记录中，标为候选，不能当作已确认事实使用。
3. **由用户确认**：让用户核对候选的准确含义，确认后再写入 Memory。用户提供或明确确认的背景可进入 `profile.md`；确认后的主题结论带着来源进入相应主题文件。用户沉默、复制交接或点击初始化都不代表确认结论。
4. **同步索引**：在 `MEMORY.md` 保留短描述和主题链接，不再复制条目正文。
5. **继续验证与纠正**：新证据改变结论时，更新条目的当前理解与状态，并追加修订记录。被撤回的旧判断仍保留在历史中，不能静默删除依据。

ASR 不确定内容保持“待回听”；未经播放核对，不能写成已回听。只有单场证据时限定为本场观察；技术回答中的识别错误不能直接变成长期能力判断。有关事实、推断、建议及单场追加规则，见 [Codex 复盘标准](codex-review.md)。

## 下一次如何读取

在 Echo 中选择本次要复盘的场次和版本，重新生成交接。Codex 使用交接给出的 Memory 绑定路径：

1. 先读 `MEMORY.md`，了解索引与阅读顺序。
2. 根据当前问题选择相关的 1–3 份主题文件；任务需要背景或偏好时再读 `profile.md`。
3. 检查条目的状态、日期和适用范围，必要时沿链接回到 `复盘.md`、转写版本与原媒体证据。
4. 用本次证据检验旧认识，提出需要确认的修订；不要用旧标签替代对本场回答的分析。

这是按索引和链接选择文件的流程，不是自动语义召回。Echo 不保证选出所有相关历史内容，也不会在刷新复盘时自动写入 Memory。当前通过文件或 Codex 阅读 Memory；单场“Codex 复盘”页签仍展示该场的 `复盘.md`。

## 虚构示例：HTTP 缓存

以下场次、ID、时间和判断全部为虚构，仅演示条目结构，不代表任何用户经历。假设用户已经回听并明确确认了候选结论，可以在 `topics/http-cache.md` 中记录：

```markdown
# HTTP 缓存

## TOPIC-HTTP-001

- 当前理解：在示例场次的 Q03 中能区分强缓存与协商缓存，但对 ETag 的比较过程解释不完整；该观察仅覆盖本题。
- 状态：已确认；练习待验证。
- 用户确认：2026-01-10 确认上述本题观察准确。
- 来源：虚构面试 DEMO-01，虚构版本 RUN-DEMO-01，Q03，原媒体 00:08:10–00:10:20；关联行动 A02。
- 证据链接：[本题复盘](../../示例公司/一面/复盘.md#q03)
- 更新时间：2026-01-10T15:00:00+08:00

### 修订历史（只追加）

- 2026-01-10：回听示例片段后，将“完全不理解缓存”的候选判断收窄为上述本题观察；用户确认。A02 练习验收：用一次请求说明 ETag、If-None-Match 和 304 的关系。
```

之后若完成练习，应先记录实际日期和验收证据，再更新当前理解并追加修订；不能仅因读过参考答案就写成已掌握。

## 私密性与备份

真实 Memory、主题证据和绑定路径均属于私人运行资料。公开仓库只包含程序模板、协议和明确虚构的示例，不能提交用户的真实画像或面试结论。

备份时包含实际绑定的整个 Memory 目录及运行数据目录中的绑定配置，即使 Memory 已不在当前转写输出目录中。备份与恢复的其他要求见 [使用指南](usage.md#隐私与备份)。
