# 可搬迁资料库与备考工作流

Echo 的源码和个人资料库分开保存。升级源码不应要求重建笔记、版本和复盘。旧目录仍可读取；需要统一整理时，使用显式迁移工具，先预览再执行。

## 整理后的结构

```text
面试资料/
├── 原有场次目录/录屏.mov
└── echo/
    ├── library.json                 # 资料库 ID 与场次目录索引
    ├── .state/                      # SQLite、笔记修订、队列、配置、播放位置
    ├── interviews/
    │   └── 公司A/日期_轮次_ID前缀/
    │       ├── interview.json       # 稳定身份、原媒体引用、复盘路径、采用版本
    │       ├── 复盘.md
    │       ├── 下一轮准备.md
    │       ├── 原有附件目录/
    │       └── transcripts/<run_id>/ # 首次和后续转写都使用独立目录
    ├── reports/                     # 跨场总结与备考报告
    └── memory/                      # 已确认内容与独立归属标记
```

旧复盘名称、附件和补充文档保留，`interview.json` 显式指定主复盘与 `documents`，不靠“最新 Markdown”猜测。历史自动核对稿仍叫 `review.md`，放在转写版本里；它不作为正式复盘。单场资料的 Markdown 文件可登记在 `documents`，总览和场次面板显示这些入口。`reports/` 下的 Markdown 自动出现在“备考与积累”。

当前台账仍是一份原媒体对应一条记录；同场多段媒体的合并编辑尚未实现。场次清单提供稳定身份和扩展位置，但不能宣称已经支持多轨时间轴。迁移遇到重复媒体或不同媒体共用结果根会停止并要求核对。

## 迁移旧资料

停止旧工作台及后台任务，确认原媒体、输出和旧台账位置。默认命令只预览，不移动文件：

```sh
.venv/bin/python -m echo.migrate_library \
  --source /path/to/interviews \
  --legacy-data /path/to/previous-state
```

检查场次与版本数后，使用同一参数加 `--apply`。没有旧台账时可省略 `--legacy-data`，但不能恢复仅存在于旧 SQLite 的笔记。

工具使用原媒体 SHA-256 唯一关联转写，保留旧台账 ID、笔记修订和历史记录。只有相同唯一来源已核对时，才将复盘中的另一 ID 作为别名保存并更新机器可读标记；原文和原件保留在备份。相同内容的重复文件、来源不明或版本归属冲突不会自动合并。

执行前在源目录同级建立 `.echo-backup-<时间>-<编号>/`，逐文件校验输出备份，使用 SQLite backup API 备份台账。整理失败时恢复原输出目录，并保留失败现场。迁移过程必须离线；文件写入失败的回滚已测试，断电或强制杀进程仍需要根据备份与计划人工恢复，不能直接重复覆盖。

迁移后的运行数据是 `<资料目录>/echo/.state/`。启动时指定：

```sh
./start.command --data-dir /path/to/interviews/echo/.state
```

也可将源码的 `.local` 链接到这个已有目录。旧台账保留用于备份，不同时运行两个工作台向同一批资料写入。模型缓存不包含在迁移中；转写依赖和模型可独立安装。

## 身份、版本与路径

- 同一输入目录内重命名原媒体时，扫描只在“内容哈希唯一匹配、原路径已不存在”时复用 ID。存在两个候选时不会猜测。
- 采用版本单独保存；浏览另一个版本不会修改它，新转写也不会自动替换它。所选版本必须属于本场、已完成且结果文件存在。
- 采用版本缺失时明确提示，临时展示可用历史版本。正式复盘引用的版本不同于当前浏览版本时显示提示。
- `interview.json` 保存相对原媒体路径；资料库清单保存相对场次目录。SQLite 保留查询和修订所需路径，整个资料库移动后显式重关联。
- 整理后的资料库暂不通过设置直接切换输入或输出位置；通过另一个资料库的 `.state` 启动，避免旧清单混入新来源。

停止服务，整体搬迁原媒体与 `echo/` 后运行：

```sh
.venv/bin/python -m echo.storage --data-dir /new/path/interviews/echo/.state --relink
```

重关联核对媒体内容、保留 ID，并备份台账后更新媒体与转写位置。Memory 使用资料库 ID 核验归属，同时更新位置元数据；不会修改 Memory 正文。仅移动部分资料或改变媒体内容时需另行核对。

## 使用总览与备考

“总览与备考”展示场次、已有转写、复盘文档及待回听/练习数，提供场次资料和跨场报告入口。已有复盘文档不等于用户确认完成；保留 Markdown 中的实际状态。准备类材料优先展示对应场次。

单场页面可以“设为采用版本”；交给 Codex 时仍以当前明确选择的版本为准。回听位置写入本地运行数据，暂停或播放中定期保存；总览提供“从这里继续”。位置恢复是尽力保存，突然断电可能丢失最后几秒；笔记仍使用独立的修订和冲突处理机制。

资料正文通过安全的 DOM 文本节点呈现标题、表格、列表和代码，不执行 Markdown 中的 HTML、脚本或指令。资料链接原文保留，当前阅读器不执行本机文件链接。需要修改文档时使用编辑器或 Codex，然后刷新。

## 备份边界

完整备份包括原媒体、整个 `echo/`、以及仍被引用的外部材料。SQLite 备份需要停止服务或使用 backup API。源码 GitHub 只保存通用程序、文档和合成测试；个人面试、备考稿、笔记、Memory、路径和迁移报告不提交。
